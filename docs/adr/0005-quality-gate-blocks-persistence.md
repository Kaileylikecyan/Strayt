# ADR-0005 质量门控在入库前拦，拒收也要记账

- 状态：已采纳
- 日期：2026-09-27
- 关联：`app/align/quality.py`、`app/persist.py`（`SaveOutcome.REJECTED`）、`app/jobs/engine.py`（`_absorb`）

## 背景

对齐结果质量参差：LLM 可能漏配、多配，或某一边整段是空的。如果这些直接入库，用户在
背诵舱里会看到"中文一段，英文是空的"。

## 决策

入库前过 `app/align/quality.py` 的门控。不合格的**一篇都不写** `pieces` / `pairs`，
但要在 `jobs.failed_units_json` 里留下可读的失败原因，让用户知道这篇为什么没进来、能
怎么处理。

阈值按真实数据标定（不是拍脑袋）：

| 常量 | 值 | 由来 |
|---|---|---|
| `MIN_SPREAD` | 1.25 | 样板上正常篇目的中英对数比下界 |
| `MAX_SPREAD` | 8.0 | 同上界 |
| `MAX_ONE_SIDED_ABS` | 3 | 允许 3 个以内的单边对（标题残留等） |
| `MAX_ONE_SIDED_RATIO` | 0.08 | 单边对占比上限 |

## 理由

- **不修正、只拦。** 自动"修"（删掉单边对、按长度重新配）会把对齐结果变成第二次对齐
  的产物，而用户看到的预览和入库的就不一样了。宁可让用户知道这一篇不行。
- **拒收也算"处理过"。** `done` 计入 `done_units`，任务能走到 100% 结束 —— 否则
  "3 篇不合格"会让进度条永远停在 75%，用户以为任务卡死。`units_json.status` 保留
  `failed` 以便界面区分。
- **模型调用花了钱就记账。** 拒收的篇目照样调过模型，`ledger.cost.add()` 在检查结果
  之前无条件执行。报 0 元会让人以为免费，从而毫无节制地重跑。

## 后果

- 通道 B（规范排版直配）在样板上是 1 `ok` / 11 `degraded` —— 这是**如实反映**：源 PDF
  的排版本来就不是严格交替。质量门控没有把 B 调好，它只是不再把坏的伪装成好的。
- 拒收原因写进 `jobs.error` 时截断到 2000 字符，避免超长 LLM 报错撑爆字段。
