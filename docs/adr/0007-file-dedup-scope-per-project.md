# ADR-0007 文件去重以 (project_id, sha256) 为界

- 状态：已采纳
- 日期：2026-09-29
- 关联：`app/db/models.py`（`File`）、`app/api/routers/files.py`（`_attach_file`）、
  `app/storage/`、`alembic/versions/c7e14b83a2d9_files_dedup_per_project.py`、
  `tests/test_files.py::test_sha_dedup_is_per_project`

## 背景

去重的动机很实在：同一份资料往往要进多个项目（同一本范文在「背诵」和「图谱」两个项目里
各跑一次），重复存几百 MB 磁盘纯属浪费，所以 `files` 一直按 `sha256` 去重、
实体文件按内容寻址存在 `storage/` 里复用（AGENTS.md §3 红线 3）。

最初的约束写成了 `UNIQUE(sha256)`——**全局一份 File 行**。代码里 `_attach_file` 明明是
「同项目复用、跨项目新建」的意思，但全局唯一索引让它做不到：跨项目传同一份资料时
`INSERT` 撞唯一键，落到 `except` 分支复用**上一个项目的行**，于是新项目名下拿不到自己的
File 行，建任务时 409「文件不属于该项目」。真实数据联调（`scripts/smoke_http.py`）
第一次跑就撞上了：单测里没人把同一份 PDF 传进两个项目。

## 决策

1. **唯一键改成 `UNIQUE(project_id, sha256)`**：File 行是「这份资料在这个项目里的身份」，
   同一内容在不同项目下是两条独立的行，语义上本来就是两件事（归属、通道标注、加工结果
   都跟项目走）。
2. **磁盘实体仍然只存一份**：`storage/` 按 `sha256` 寻址落盘，第二次上传发现文件已存在就
   跳过写盘、只复用 `server_path`。省的是磁盘，不是数据库行。
3. **`_attach_file` 的查询条件与唯一键保持一致**（`project_id` + `sha256` 同时过滤），
   免得约束和代码各说各话。

## 理由

- 约束要和领域身份一致。File 行的 `project_id` 是外键到 Project，删除项目要级联清理自己的
  File 行；如果一行能被两个项目共享，级联删除就永远删不干净。
- 内容寻址的存储复用已经拿到「不重复占磁盘」的全部收益，没有理由再让数据库行做跨项目共享。
- 代价是多几行元数据（每项目一行，几十字节），相对于被破坏的级联语义完全可以接受。

## 后果

- 迁移 `c7e14b83a2d9` 会把已有库的唯一索引换成组合索引；已存在的跨项目"共享行"保持原样
  （它们本来就是当初传错项目的结果），重新上传会得到正确的独立行。
- 单测锚点：同项目重复上传仍复用同一行（`test_sha_dedup_reuses_row`），
  跨项目同内容必须是两条行且各自能建任务（`test_sha_dedup_is_per_project`）。
- **别再把它"优化"回全局唯一**。要省的是磁盘，`storage/` 已经在省了。
